## 1. 보존할 핵심 경험
1. 판례로 법정의 성향을 내 역사로 바꾸는 장기 계획.
2. 세 사람을 각자 움직인다. 그리고 그 셋도 이 식민지에 산다.
3. 판결은 집행되고, 줄 선 사람들의 사정은 기다리는 동안 나빠진다.

## 2. 설계 목표 (변경만)
- Jev와 무관한 산술 지름길 0개(S07).
- 표시 = 실제를 유지하면서 숫자보다 사람(판정관 기울기, 줄 선 주민)을 보여 준다.

## 3. 핵심 루프
```
[주기] 줄 선 주민(사건) 확인 · 경쟁자 의도 확인 → (선택) 합의 1회 · 예비 심리
     → 사건 1개 상정 + 주목 사실 1개 → 판정관 3명 판정 → 판결
     → 판례 기록(주민 이름·표결) → 집행(주민·판정관 상태) → 대기 압박 → 트리거 사건
  ×6주기 → 최종 심리
```

## 5. Jev 판정 명세 (ENGINE 스키마 "A03")

### 5.1 J1 판정관 판결 (ACT)
- 입력
  - memory: 판례 목록(시간 순)
  - log: 판정관 의견 이력 + 개인 기록
  - context: 사건 ID, 주목 사실 ID, 당사자 상태 태그
  - persona: 경험 문장 3개
- 질문: J1a "판정관 {이름}은 이 청구를 어떻게 판결하는가?" 인정 / 부분 인정 / 기각. J1b(FACTOR) 판례들 / 먼저 확인한 사실 / 다른 사실 / 자기 기록 / 없음.
- **확률 처리**:
  - c_j = P_raw(인정) + 0.5 × P_raw(부분) → 구간화 c_j' ∈ {0.1, 0.3, 0.5, 0.7, 0.9}(경계 0.2/0.4/0.6/0.8, 원시값 고정)
  - S = (c_1' + c_2' + c_3') / 3
  - 판결: S ≥ 0.55 인정 / 0.40 ≤ S < 0.55 부분 인정 / S < 0.40 기각
  - 개별 투표: J1a 원시 1위. 원시 마진 < 0.10이면 기권. 판례 표결 표기와 의견 이력에 쓴다.
- 캐시 키: ENGINE 3.1(판례 순서 포함). 판례 문장의 주민 상태가 바뀌면 키가 바뀐다(의도된 동작).
- 사전 계산(L0): 판례 0개 × 의견 이력 없음 × 개인 기록 없음 상태의 (사건 × 사실 × 판정관). 플레이어 사건 20 + 회사 사건 10 + 최종 1 = 31 × 3 × 3 = 279질문.
- 대체 함수: 7.1 손 표. 결과는 L2에만 기록한다.

### 5.2 판당 호출 상한
- v01과 같다(플레이어 사건 5 + 경쟁자 3 + 예비 심리 5 + 최종 1 + 재시도 6 = **20**). 합의로 경쟁자 사건이 취소되면 1 줄어든다.

## 6. 규칙과 종료 조건 (변경만)

### 6.1 주기 순서
1. 경쟁자 주기면: (합의 사용 시 취소) 아니면 경쟁자 사건 판결 → 판례 → 집행.
2. 플레이어: 예비 심리(선택) → 줄 선 주민 1명의 사건 상정 + 주목 사실 → 판결 → 판례 → 집행(판정관 영향 칸 포함).
3. 의견 이력 갱신(무게 변화 없음).
4. 대기 압박 적용 → 트리거 사건(새 주민이 줄에 섬) → 빈칸 보충.
5. 판례 문장의 주민 상태 갱신. 다음 경쟁자 의도 공개.

### 6.2 최종 심리·종료
- v01과 같다. 남은 예비 심리 토큰은 2개당 주목 사실 1개로 바꾼다. 퇴거 3명이 되는 순간 즉시 패배한다(판결이든 대기 압박이든).

## 7. 원칙 2 경험 테스트

### 7.1 가장 강한 손 표(측정 전 고정)
- v01의 손 표(사건 쌍 유사도 0/1/2 × 방향 × 판정관 태그 가중치)에 다음을 더한다.
  - **완고 규칙**: 판정관이 직전 소수 의견이면, 같은 주제 태그 사건에서 자기 이전 방향으로 +1구간.
  - **개인 기록 규칙**: 판정관 개인 기록의 주제 태그와 사건 태그가 겹치면 그 기록의 방향으로 +1구간.
  - **판례 주민 상태 규칙**: 판례 주민이 "퇴거·불안"이면 그 판례의 효과 −1(판결의 결과가 나빴음).
- 디자이너가 판정관 3명 × 태그 6개 × 규칙 3종으로 만들 법한 표다(약 60칸).

### 7.2 Jev만의 차이(가설)
1. 간접 사다리(판례 → 판례 → 최종 사건).
2. 판정관별 소수 의견 반응 차이(미로는 물러서고 오렌은 버팀). 손 표는 전원 완고 +1.
3. 판례 주민의 현재 상태에 대한 해석 차이(하스는 퇴거된 판례 주민에 동정, 오렌은 무시).

## 8. 대표 플레이 예시 (v02)
- 판정관 경험 문장: 하스("광산에서 손가락 두 개를 잃었다", "조합 창립 멤버의 딸", "공구를 빌려준 적이 많다"), 오렌("회사 법무팀 20년", "계약서 없는 약속에 두 번 배신당했다", "질서가 사람을 지킨다고 믿는다"), 미로("판례를 외우는 것이 취미", "누구 편도 들지 않으려 애쓴다", "한 번 틀린 판결로 이웃을 잃었다").
1. 1주기. 줄: 노아(벌집, 대기 0), 바투(정수기 개선, 대기 0), 세린(세탁기 수리비), 유이(화물칸). 노아를 상정, 주목 사실 "3년간 벌을 돌봤다". 원시 c: 하스 0.88 → 0.9, 미로 0.62 → 0.7, 오렌 0.18 → 0.1. S = 0.57 → **인정**(2:1, 오렌 반대). 판례 1: "노아 사건: … → 인정(2:1, 오렌 반대) / 노아는 지금 생계 안정". 화면: 하스·미로 "기울어 있음", 오렌 "반대".
2. 2주기 경쟁자 사건 공개: "계약서 없는 작업 성과는 고용주 소유". 합의(1회)를 쓰면 막을 수 있지만, 그 대가로 당사자인 바투가 거주 임시로 떨어진다. 바투는 이미 대기 2주기째다. 합의하지 않기로 한다.
3. 회사 판례 성립(2:1, 하스 반대). 오렌의 의견 이력: 노아 사건 소수 → 이번 다수. 하스: 이번 소수. 무게 변화는 없다. 다음 노동 사건에서 하스가 더 완고해질지는 Jev의 몫이다.
4. 대기 압박: 바투(대기 2) → 생계 불안. 세린 대기 1. 바투를 먼저 올릴 것인가, 최종 사건과 가까운 트리거 사건(새로 줄에 선 "드론 정비공 키아")을 올릴 것인가.

## 12. 종이 프로토타입 규칙 요약 (1쪽, v02)

**준비물**: v01 + 판정관 카드에 경험 문장·의견 이력 칸·개인 기록 칸, 줄 선 주민 4칸 보드와 대기 카운터, 회사 사건 10장, 합의 토큰 1. 무게 칸은 없음.

**Jev 역할**(판정관마다 1명 권장, Q19): 판정관 카드, 판례 기록지(주민 상태 포함), 이번 사건만 본다. 인정·부분·기각 각각에 확률을 적는다(합 1). 가장 의지한 것 1개. 설명은 금지한다. 같은 입력이면 같은 답. 오류 주입은 주사위 6.

**계산**(진행자): c = 인정 + 0.5 × 부분 → 구간(0.1/0.3/0.5/0.7/0.9) → S = 평균 → 0.55 이상 인정 / 0.40 이상 부분 / 미만 기각. 플레이어에게는 판정관 기울기(0.7 이상 기울어 있음 / 0.5 고민 중 / 0.3 이하 반대)와 S의 위치(기각 쪽/팽팽/인정 쪽)만 알린다.

**주기 진행**: 경쟁자 사건(합의 가능) → 예비 심리 → 상정 + 주목 사실 → 판결 → 판례(이름·표결·상태) → 집행(주민·판정관) → 의견 이력 → 대기 압박(대기 2주기마다 한 단계 하락) → 새 주민 줄 서기 → 경쟁자 의도 공개.

**종료**: 6주기 후 최종 심리. 퇴거 3명이면 즉시 패배.

**기록할 것**: 판정관별 투표 예측과 실제, 놀람/납득, "누구를 먼저 올릴지" 발화, 합의 사용 여부와 이유, 판례 그래프 회고.

**손 표 버전**: 진행자가 7.1 표로 계산한다(블라인드).
