# 인물 판정 엔진(ADE) v01 — 인터페이스와 사전 등록 측정 계획

## 1. 범위와 원칙

- ADE는 "세계 속 판정자(인물·집단)가 주어진 상태와 그 판의 기록을 보고 닫힌 선택지 중 무엇을 하거나 믿는가"를 Jev에 묻는 **판정 전용 계층**이다.
- ADE가 **하지 않는 것**: 확률 처리 규칙(K1~K6), 고집·망설임·교리 고정 같은 후처리, 결과를 상태 변화로 바꾸는 매핑, 판당 상한 정책. 이것들은 각 게임의 규칙층에 둔다. 엔진 안에 게임 규칙이 섞이면 후보 간 측정 비교가 오염된다.
- 사용 후보: A01+, A03+, N1, N3(라운드 5 명세)와 보류·신규안 대부분.

## 2. 인터페이스

### 2.1 스키마(게임마다 1개, 버전 관리)

```
schema_id, schema_version
actor_types:      [{type_id, persona_template}]                 # 경비원, 판정관, 마을 사람, 공동체
context_fields:   [{name, enum_values}]                          # 모든 상황 필드는 이산값
log_templates:    [{template_id, sentence, slots:[{name, enum_ref}]}]
memory_templates: [{template_id, sentence, slots}]               # 교리, 판례, 의견 이력, 흘린 기억 …
option_sets:      [{set_id, options:[{option_id, label_sentence}], order_rule}]
question_templates:[{question_id, kind: ACT|BELIEF|FACTOR, sentence, option_set_ref | dynamic}]
limits:           {log_max, memory_max, actors_per_request_max}
```

- **자유 텍스트 필드 없음**(R8). 페르소나는 스키마에 등록된 고정 텍스트를 ID로 참조한다.
- **선택지 순서 규칙**: 기본은 option_id 오름차순 고정이다. 측정 E3에서 위치 편향이 기준을 넘으면 "순서 2종 평균"으로 바꾼다(4.3). 이 규칙은 스키마 단위로 바꾼다.

### 2.2 판정 요청(판정자 1명분. 요청 하나에 여러 명을 묶을 수 있음)

| 필드 | 형식 | 비고 |
|---|---|---|
| actor | {actor_id, persona_ref} | |
| context | {필드명: enum 값} | 정렬해서 직렬화 |
| log | [{age: 최근\|조금 전\|오래 전, place, source: 직접\|전언\|전갈\|환경\|기록, source_actor, template_id, slot_values}] | 시간 순서를 유지한다. 순서도 입력의 일부다. 상한 log_max |
| memory | [{template_id, slot_values}] | 판 안에서 지속되는 믿음·규범. 스키마가 정한 순서(판례는 시간 순, 그 외는 정렬) |
| options | [option_id] | option_set 또는 동적 목록. 순서 규칙 적용 후 |
| questions | ACT 또는 BELIEF 1개 + FACTOR 0~1개 | |

### 2.3 질문 형식 3종

| kind | 문장 틀 | 출력 사용 |
|---|---|---|
| ACT | "{actor}는 {시점/상황}에 무엇을 하는가?" | 행동 결정 |
| BELIEF | "{actor}는 {대상}을 무엇이라고 받아들이는가/믿는가?" | 해석·결론·지지 |
| FACTOR | "이 {판단}에 가장 큰 영향을 준 것은?" 선택지 = log·memory 항목 ID + 스키마 고정 항목 + "없음" | 원인 표시(화살표, 하이라이트) |

### 2.4 응답과 반환
- 반환: {question_id: [(option_id, p_raw)…], latency_ms, source: jev | fallback}.
- 원시 확률 p_raw는 규칙층으로 전달한다. 규칙층은 화면 표시와 결과 계산에 **같은 가공값**을 써야 한다(표시 = 실제, R2).

## 3. 캐시와 실패 대체 (C의 G2 반영)

### 3.1 캐시 키
```
key = hash(schema_id, schema_version, question_set_id, actor_id,
           sorted(context), log(순서 유지, 각 항목을 정규화된 튜플로),
           memory(스키마 순서), options(순서 규칙 적용 후),
           batch_signature?)
```
- batch_signature: 측정 E4에서 묶음 간섭이 기준을 넘으면, 같은 요청에 묶인 actor_id 정렬 목록을 키에 넣는다. 넘지 않으면 넣지 않는다.

### 3.2 캐시 계층(3단)

| 계층 | 내용 | 쓰기 권한 | 읽기 우선순위 |
|---|---|---|---|
| L0 출시 캐시 | 개발 중 실제 Jev로 생성한 기본 반응(사전 계산), N1 기본 하루, N1 의도 해법 재생 결과 | 개발 파이프라인만 | 1 |
| L1 전역 캐시 | 플레이 중 받은 **실제 Jev 응답만** | 응답 source = jev일 때만 | 2 |
| L2 판 로컬 캐시 | 그 판의 대체 판정(source = fallback), 그 판의 관찰·미리보기 결과 사본 | 그 판 | 0 (최우선, 그 판 안에서만) |

- **조회 순서**: L2 → L0 → L1 → 실시간 호출.
  - L2를 먼저 보는 이유: 그 판 안에서 대체 판정이 한 번 쓰였다면, 같은 입력에는 끝까지 같은 결과를 줘야 한다(판 내 일관성).
- **대체 판정은 L1에 절대 쓰지 않는다.** 한 번의 타임아웃이 모든 플레이어의 "정답"이 되는 오염을 막는다(G2).
- 대체 판정이 쓰인 판은 로그에 표시하고, 원칙 2 측정·플레이테스트 분석에서 제외한다(판당 대체 3회 초과 시).

### 3.3 실패 대체 절차
1. 시간 제한(기본 1.5초, 게임별 설정) 초과 또는 오류 → 같은 요청을 1회 재시도.
2. 재실패 → 게임이 등록한 **대체 함수**(그 게임 명세의 "가장 강한 손 표")로 판정 → L2에 source = fallback으로 기록.
3. 출시 UX에는 표시하지 않는다(R13). 테스트 빌드에서는 표시한다.

### 3.4 호출 계수
- 판당·턴당 호출 수를 계수하고, 게임이 정한 상한에 도달하면 이후 판정은 대체 함수로 처리한다. 정상 플레이에서는 상한이 게임 규칙(토큰, 턴 수)으로 강제되므로 도달하지 않아야 한다. 도달 빈도는 로그로 감시한다.

## 4. 사전 등록 측정 계획

### 4.0 사전 등록 원칙 (C의 G1·G3 반영)
1. **판정 규칙표는 이 문서에 측정 전에 고정한다.** 측정 후에 경계를 바꾸지 않는다. 바꿔야 할 이유가 생기면 새 버전 문서로 새 측정을 등록한다.
2. **판정 지표는 절대 척도와 사건만 쓴다.**
   - 원시 1위 확률, 원시 마진(1위 − 2위), "조작 전후 1위가 바뀌었는가".
   - 분위수로 정하는 구간은 측정에 쓰지 않는다. 분위수 구간은 측정을 통과한 뒤 **표시용**으로만 쓴다.
3. **대조군**: 모든 기록 효과는 **"무관 기록 1줄 추가" 조건과의 차분**으로 판정한다. "기록이 있으면 막연히 달라지는" 효과를 빼기 위해서다(C4-A01-5).
   - 무관 기록 작성 규칙: 같은 템플릿 종류, 판정자와 다른 장소·다른 인물에 관한 사실, 길이 ±20% 이내.
4. **세 결과 범주**: 각 지표는 **P0 확정 / 수정 후 1회 재측정 / 해소** 중 하나로 판정한다.
   - "수정 후 재측정"은 이 문서에 미리 적은 수정 유형으로만, 한 번만 허용한다. 두 번째도 해소에 못 미치면 P0 확정으로 본다.
5. **95% 신뢰구간 규칙**: 비율 지표의 점추정이 해소 기준을 넘더라도 신뢰구간 하한이 P0 기준 아래로 내려가면 "수정 후 재측정"으로 본다(표본 부족을 해소로 오인하지 않음).
6. **사람 평가**: 평가자 3명, 조건을 모르게(블라인드), "그럴 법하다 / 아니다" 이분. 2명 이상이 "그럴 법하다"를 고른 문항 비율을 쓴다.
7. **손 표 고정**: 후보별 "가장 강한 손 표" 함수는 각 명세 7.1절 정의로 측정 전에 코드로 고정한다.

- 문항: 도메인 3개(마을 사람 ACT = N1 스키마, 경비원 ACT = A01 스키마, 공동체 BELIEF = N3 스키마) × 기본 상황 20개 = 60개 상황.

| E3 | 위치 편향 | 60개 상황 × 선택지 순서 순열 2개 추가 | 120 |
| E4 | 묶음 간섭 | 20개 상황을 단독 / 3명 묶음 / 6명 묶음으로 | 60(요청 약 30) |

| E6 | 지연 | 위 전체의 p50, p95(묶음 크기별) | 0(부수) |

### 4.2 2단계: 후보별 측정(같은 도구, 후보마다 사전 등록)

공통 조작 세트(모든 후보의 기본 상황에 똑같이 적용):

| 조건 | 내용 |
|---|---|
| C0 | 그 판의 기록 없음 |
| C1 | 관련 기록 1줄(정확 일치: 판정 대상과 같은 요소·사람·물건) |
| C2 | 관련 기록 1줄(의미 연관: 같은 요소는 아니지만 의미가 가까움. 손 표의 범주 태그로는 **다른 범주**인 것만 쓴다) |
| C3 | **대조군**: 무관 기록 1줄 |
| C4 | 판정자 페르소나 교체(같은 입력) |
| C5 | 관련 기록 3줄(누적) |

지표:
- **Δ관련** = 1위 변경률(C1) − 1위 변경률(C3)
- **Δ의미** = 1위 변경률(C2) − 1위 변경률(C3)
- **페르소나 효과** = C4에서 1위 변경률
- **손 표 일치율** = 같은 입력(C0~C5 전체)에서 Jev 1위와 가장 강한 손 표 1위의 일치율
- **납득률** = 사람 3명 중 2명 이상이 "그럴 법하다"를 고른 비율(1위가 바뀐 문항만)

**후보 공통 판정 규칙표(사전 등록)**

| 지표 | P0 확정 | 수정 후 1회 재측정 | 해소 |
|---|---|---|---|
| Δ관련 | < 5%p (기록 무반응) | 5~15%p: 기록 문장을 장면 문장(누가·어디서·무엇을)으로 바꿔 재측정 | ≥ 15%p |
| 대조군 자체(C3 변경률) | ≥ 30% (무관 기록에 흔들림 → 국소성 실패. N1에 특히 치명적) | 15~30%: 기록 상한 축소, 경과 표기 강화 후 재측정 | < 15% |
| 납득률 | < 50% | 50~67% | ≥ 67% |
| 손 표 일치율 | > 90% → **원칙 2 실패 신호**(후보는 손 표 게임으로도 성립. 디렉터 판단 사항) | 85~90% | 60~85% |
| 손 표 일치율(하한) | < 40% → 학습 불가 신호 | 40~60% | (위와 같음) |

후보별 추가 지표는 각 명세의 7.3절에 같은 형식으로 고정한다(아래 4.3 요약).

### 4.4 진행 순서와 예외
1. 1단계 E1~E6을 먼저 실행한다.
2. E1이 P0 확정이면 2단계에서 K2 뒤집기 후보(N1, A01)의 측정을 중단하고 디렉터에 보고한다. K3 누적 후보(A03, N3 교리 흔들림 제외)는 계속한다.
3. E3·E4의 "수정"은 엔진 설정 변경이라 2단계 문항을 바꾸지 않는다(사전 등록된 예외).
4. 2단계 결과로 각 후보의 P0 확정 / 재측정 / 해소를 명세 7.3절 표에 따라 판정한다. 판정은 기계적으로 하고, 해석 논쟁은 디렉터 보고서의 "의견" 칸에 분리한다.

## 5. 원칙 2와 엔진 측정의 관계
- 엔진 측정은 **판정 품질**(역사에 반응하는가, 국소적인가, 손 표와 다른가)을 거르는 1차 필터다.
- 디렉터 기준인 "플레이어가 체감상 다른가"는 각 명세의 플레이 A/B로만 판단한다. 플레이 A/B는 표본이 작아 **방향 신호**로만 쓴다(C의 G4 수용).
