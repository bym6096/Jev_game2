# SPEC A03+ 세 판정관과 집행되는 판결 — 플레이테스트 가능한 최소 규칙 명세

## 1. 선정 아이디어와 보존할 핵심 경험

- 아이디어: A03+ (A-ALT-v01). 기반 패턴: B-P08(기록 슬롯 큐레이션), B-P02(확신의 저울), B-P06(경쟁자 공개 의도).
- **보존할 핵심 경험 3가지**
  1. **"법정의 성향을 내 역사로 바꾼다"**: 작은 판결을 쌓아 최종 사건에 이르는 몇 수 앞의 계획.
  2. **"세 사람을 각자 움직인다"**: 판정관 셋은 같은 판례에 다르게 반응한다. 한 명만 공략하면 반발이 커진다.
  3. **"판결은 집행된다"**: 판결이 이름 있는 주민의 삶을 실제로 바꾸고, 그 결과가 새 사건을 만든다. 이긴 판결이 식민지를 흔들 수도 있다.

## 2. 설계 목표와 명시적 가정

| 목표 | 규칙 결정 |
|---|---|
| 원칙 1: 플레이어는 논증을 제출하지 않는다(C-A03 원칙 1 지적) | 쟁점 카드를 **주목 사실 카드**로 바꾼다. 사건에 이미 적혀 있는 사실 3개 중 1개를 "법정이 먼저 볼 사실"로 고르는 것뿐이다. 판정 질문은 "이 판정관은 어떻게 판결하는가"이고 플레이어의 주장을 평가하지 않는다. |
| 판정관 상태가 결과를 바꾼다(Q3) | 판정관 3명의 페르소나, 무게, 소수 의견 기록이 입력에 들어간다. |
| 원칙 2: 판정 입력에 그 판의 역사 | 판례 목록(최대 6), 직전 집행 결과, 판정관의 소수 의견 이력. 사건 후보 자체도 집행 결과로 생성된다. |
| 극단 확률에 강한 처리(C-R16) | 판정관 3명의 확률을 무게와 함께 누적하는 K3. 한 판정관의 극단값이 결과 전체를 정하지 않는다. |
| 유사도 게임 붕괴 방지(C-A03-1) | 최종 사건과 주제 태그가 2개 이상 겹치는 사건은 기본 후보 풀에 없다. 집행 트리거로만 생긴다(얻어야 하는 사건). |
| 결과가 장면으로 보인다(Q7) | 판결마다 집행 장면: 주민 상태 태그 변화 + 템플릿 문장 1개. |
| 비용 확정 | 판당 실시간 요청 상한은 20이다. |

## 3. 핵심 루프

```
[회기 시작] 최종 사건 공개(판례 없을 때 가중 점수 표시) · 판정관 3명 · 주민 8명 · 사건 후보 4개
  ↓  ×6주기
[주기] 경쟁자 의도 확인 → 사건 1개 선택 + 주목 사실 1개 선택 → (선택) 예비 심리
     → 판결(판정관 3명 동시 판정, 누적 점수) → 판례 목록에 추가 → 집행(주민 상태 변화)
     → 집행 트리거로 새 사건 후보 생성 → 소수 의견·무게 갱신
  ↓
[최종 심리] 최종 사건 판결 → 승리/부분 승리/패배 (+ 식민지 안정 조건)
```

- **목표**: 최종 사건에서 "인정"을 얻는다. 동시에 식민지 안정(퇴거 주민 3명 미만)을 유지한다.
- **행동**: 사건 선택, 주목 사실 선택, 예비 심리 사용, 판례 고정, 사건 보류(4.2).
- **제약**: 6주기, 예비 심리 5회, 판례 슬롯 6칸, 고정 토큰 2개.
- **정보**: 판정관별 직전 투표와 의지한 판례(요인 하이라이트), 판정관 무게, 경쟁자 다음 사건, 최종 사건 현재 점수(예비 심리로만 갱신).
- **보상**: 유리한 판례, 주민 상태 개선, 새 사건 후보.
- **실패**: 최종 사건 기각, 또는 퇴거 주민 3명 이상(식민지 소요 → 즉시 패배).

## 4. 게임 상태와 행동

### 4.1 게임 상태

| 상태 | 형식 |
|---|---|
| 최종 사건 | 사건 카드 1장(사실 3개, 주제 태그 3개, 당사자 2명) |
| 판정관 3명 | id, 페르소나 3문장(고정), 무게(초기 1.0, 최대 2.0), 소수 의견 카운터(0~1) |
| 판례 목록 | 최대 6항목, 시간 순서. 항목 = (사건 요약 1문장, 판결, 주목 사실, 표결 표기 예: "2:1, 오렌 반대"), 고정 여부 |
| 사건 후보 | 4칸. 각 사건 = 사실 3개, 주제 태그 3개, 당사자(주민), 판결별 집행 효과 3종, 트리거 조건 |
| 주민 8명 | 이름, 상태 태그 4종(거주: 정착/임시/퇴거, 생계: 안정/불안, 소유물 목록, 관계 태그) |
| 경쟁자(회사 변호인) | 다음 상정 예정 사건(1주기 전 공개), 상정 주기: 2·4·6주기 |
| 자원 | 예비 심리 5, 판례 고정 토큰 2, 보류 토큰 1 |

### 4.2 행동

| 행동 | 효과 |
|---|---|
| 사건 상정 | 후보 4개 중 1개를 이번 주기에 판결받는다. |
| 주목 사실 선택 | 상정 사건의 사실 3개 중 1개에 표시. 판정 입력에서 그 사실이 "법정이 먼저 확인한 사실"로 맨 앞에 온다. |
| 예비 심리 | 토큰 1을 써서 (사건, 주목 사실) 조합 또는 최종 사건의 현재 판정을 미리 본다. 결과는 캐시되어, 같은 주기에 같은 조합을 상정하면 그대로 확정된다(표시 = 실제). |
| 판례 고정 | 고정 토큰 1. 해당 판례는 슬롯이 넘쳐도 밀려나지 않는다. |
| 보류 | 토큰 1. 이번 주기에 사건을 상정하지 않는다. 경쟁자 사건만 판결된다. 후보 1개를 버리고 새로 뽑는다. |

### 4.3 판결과 상태 변화
- 판결 3종(플레이어 측 기준): **인정 / 부분 인정 / 기각**.
- 판례 목록에 추가된다(6칸 초과 시 가장 오래된 비고정 판례 삭제).
- 사건 카드에 적힌 판결별 집행 효과를 적용한다. 예: "조합 작업장 공동 소유 — 인정: 정비공 '바투' 생계 안정, 회사 관리인 '세린' 관계 태그 '조합과 적대' 추가 / 기각: 바투 거주 → 임시".
- 집행 결과가 트리거 조건을 만족하는 사건 템플릿이 있으면 후보 풀에 추가된다(6.3).

## 5. Jev 판정 명세

### 5.0 공통
- 직렬화 템플릿 고정. 판례 목록은 **시간 순서 그대로** 둔다(정렬하지 않음). 순서가 게임 요소이기 때문이다. 순서 효과가 실측에서 없으면 v02에서 정렬로 바꾸고 순서 결정을 제거한다.
- 캐시: 판 간 전역 캐시. 입력에 판례 목록이 들어가므로 같은 입력은 사실상 같은 역사에서만 나온다.
- 확률 구간: 판정관별 확률은 5구간(0.05 / 0.25 / 0.5 / 0.75 / 0.95, 실측 분위수로 재설정)으로 바꾼 값만 계산과 표시에 쓴다(R2).
- 하드 규칙: 없음. 정답이 분명한 판정이 아니라 해석 판정이므로 하드 규칙을 두지 않는다. 대신 사건 콘텐츠 작성 규칙으로 "판례 없을 때 경계 사례"를 보장한다.

### 5.1 J1 판정관 판결 (주 판정)

**입력 상태 형식**(한 요청에 판정관 3명분)

```
[법정] 식민지 자동 법정 합의부. 판정관은 각자 판결한다.
[판례] (오래된 것부터, 최대 6개)
  1. {사건 요약 1문장} → {인정|부분 인정|기각} (먼저 확인한 사실: {사실}) (표결: {2:1, 이름 반대 | 3:0})
  ...
[이번 사건] {사건 제목}
  먼저 확인한 사실: {주목 사실}
  다른 사실: {사실 2}, {사실 3}
  당사자: {주민 A 이름, 상태 태그} 대 {주민 B 또는 회사}
[판정관 {이름}] {페르소나 3문장} / 최근 소수 의견: {있음(사건명)|없음}
```

**질문 J1a**(choice, 판정관마다): "판정관 {이름}은 이 사건에서 {플레이어 측 당사자}의 청구를 어떻게 판결하는가?"
- 선택지: 인정 / 부분 인정 / 기각

**질문 J1b**(choice, 판정관마다, 같은 요청): "판정관 {이름}이 이 판결에서 가장 크게 의지한 것은?"
- 선택지: 판례 1~6 중 존재하는 것 / 먼저 확인한 사실 / 다른 사실 / 없음
- 결과: 판결 화면에서 해당 판례에 판정관 색의 선이 그어진다. 회기 끝에는 판례 그래프가 남는다(C-A03-3, C-R08).

**확률 처리**(K3 누적 + K2 개별 투표)
- 판정관 j의 기여 c_j = 무게_j × (구간화 P(인정) + 0.5 × 구간화 P(부분 인정)).
- 가중 점수 S = Σ c_j / Σ 무게_j (0~1).
- 판결: S ≥ 0.55 인정 / 0.40 ≤ S < 0.55 부분 인정 / S < 0.40 기각. (경계값은 가설이며 실측 후 조정한다.)
- 개별 투표 = 각 판정관 J1a의 1위(K2). 표결 표기("2:1")와 소수 의견에 쓴다. 1·2위 마진이 0.10 미만이면 투표는 "기권"으로 표시하고 소수 의견에 포함하지 않는다(동점 규칙).
- 화면 표시: 판정관마다 막대(c_j)와 투표 아이콘, 합계 막대 S와 경계선 두 개.

**캐시 키**: hash(J1, 판례 목록[순서 포함, 각 항목의 사건ID·판결·주목사실ID·표결], 사건ID, 주목사실ID, 당사자 상태 태그, 판정관 3명의 [id, 소수의견 사건ID]).
- 무게는 Jev 입력에 넣지 않는다(게임 계산에만 쓴다). 판정관이 자기 무게를 의식하는 구조는 의미가 없기 때문이다.

**사전 계산 vs 실시간**
- 사전 계산: 판례 0개 상태의 (사건 × 주목 사실 × 판정관). 사건 30 × 사실 3 × 판정관 3 = 270질문. 용도는 (a) 1주기 판정(판례가 없으면 표 사용), (b) 대체 판정의 기반, (c) 손 표 버전의 기반, (d) 콘텐츠 조율(최종 사건 S가 0.40~0.60인지 확인).
- 실시간: 판례가 1개 이상인 모든 판정. 즉 2주기부터 전부 실시간이다.

### 5.2 J2 경쟁자 사건 판결
- J1과 같은 형식. 플레이어 측이 피고 측이 된다(질문의 "청구"는 회사 측 청구). 결과는 판례에 회사 측 판결로 기록된다.
- 경쟁자의 사건 선택은 **Jev를 쓰지 않는 규칙**이다. 회사는 후보 풀에서 "최종 사건 주제 태그와 겹치는 수가 가장 많은 회사 측 사건"을 고른다. 1주기 전에 공개된다(B-P06 공개 의도).

### 5.3 판당 호출 상한

| 출처 | 상한 | 강제 방법 |
|---|---|---|
| 플레이어 사건 판결(J1) | 5 | 2~6주기(1주기는 판례가 없어 표 사용) |
| 경쟁자 사건 판결(J2) | 3 | 2·4·6주기 |
| 예비 심리 | 5 | 토큰 5 |
| 최종 심리 | 1 | |
| 재시도 예비 | 6 | 실패 시 1회 재시도 |
| **합계** | **20** | |

- 판정관 3명 × 질문 2개 = 질문 6개를 요청 1개에 넣는다. 입력 약 2.5~4k 토큰(판례 6개 기준).
- 직렬 깊이: 주기당 1~2(경쟁자 판결 → 플레이어 판결 순서. 경쟁자 판결이 판례에 들어가야 하므로 직렬이다).

### 5.4 응답 실패 시 대체
- 1회 재시도 후 실패하면 **대체 판정 = 판례 0개 사전 계산 표 + 손 표 판례 보정**(7.1과 동일). 대체 결과도 캐시한다. 출시 UX에는 표시하지 않고 로그만 남긴다.

## 6. 규칙과 종료 조건

### 6.1 주기 순서(확정 규칙)
1. 경쟁자 상정 주기(2·4·6)면 경쟁자 사건을 먼저 판결한다(J2) → 판례 추가 → 집행.
2. 플레이어: 예비 심리(선택) → 사건 상정 + 주목 사실 → 판결(J1) → 판례 추가 → 집행.
3. 소수 의견 갱신: 판정관의 투표가 최종 판결(인정/부분/기각을 인정 측·기각 측으로 이분, 부분 인정은 인정 측)과 다르면 소수 의견 카운터 +1. 카운터가 2가 되면 무게 +0.5(최대 2.0), 카운터는 0으로. 기권은 변화 없음.
4. 트리거 검사 → 새 사건 생성 → 후보가 4개를 넘으면 가장 오래된 후보를 버린다. 4개 미만이면 기본 풀에서 보충한다.
5. 다음 경쟁자 의도 공개.

### 6.2 최종 심리
- 6주기 후 최종 사건을 J1과 같은 방식으로 판결한다. 주목 사실은 플레이어가 고른다.
- 남은 예비 심리 토큰 2개당 최종 사건에 주목 사실 1개를 추가로 지정할 수 있다(최대 2개). 아끼는 선택에도 의미가 생긴다(C-R04 수용).
- 결과: 인정 = 승리, 부분 인정 = 부분 승리, 기각 = 패배.

### 6.3 사건 생성 규칙(콘텐츠 형식)
- 기본 풀: 사건 템플릿 20개. 최종 사건과 주제 태그 2개 이상 겹치는 사건은 기본 풀에 넣지 않는다(C-A03-1).
- 트리거 사건: 템플릿 10개. 조건 예: "주민 X의 거주 = 임시", "판례에 '공동 소유 인정'이 있음". 조건을 만족하면 후보에 추가된다. 최종 사건과 주제가 많이 겹치는 사건은 트리거로만 나온다.
- 사건 카드 작성 규칙: 생활 사물 중심(벌집, 정수기, 공용 세탁기, 드론 경로), 사실 3개는 서로 다른 방향을 가리키게 쓴다(하나는 노동, 하나는 계약, 하나는 공동체 등). 판례 0개 상태에서 사전 계산 S가 0.30~0.70에 들도록 조율하고, 벗어나면 문장을 고친다.

### 6.4 종료 조건
- 승리: 최종 인정 + 퇴거 주민 2명 이하.
- 부분 승리: 최종 부분 인정, 또는 최종 인정이지만 퇴거 3명(아래 즉시 패배 규칙보다 우선하지 않음. 퇴거 3명이 되는 순간 즉시 패배).
- 패배: 최종 기각, 또는 어느 시점이든 퇴거 주민 3명 이상(식민지 소요).

## 7. 원칙 2 경험 테스트

### 7.1 손 표 버전 정의
- 기본: 판례 0개 사전 계산 표(Jev 버전과 동일).
- 판례 보정: 디자이너가 사건 쌍 유사도 표(사건 30 × 30, 0/1/2)와 판정관별 주제 태그 가중치(태그 6개 × 판정관 3명, −1/0/+1)를 만든다.
  - 판정관 j의 P(인정) 구간 = 기본 구간 + Σ_판례 [유사도 × 방향(같은 측 인정 +1, 반대 −1) × (1 + 태그 가중치 합)] / 2를 반올림한 구간 이동. 구간은 0~4로 자른다.
- 이것은 C-X02가 제시한 근사 모델(유사도 × 방향 × 쟁점 가중치)을 그대로 구현한 것이다.

### 7.2 체감 차이가 생길 것으로 예상하는 지점 (가설)
1. **간접 사다리**: 판례 A("벌이 만든 벌집은 돌본 자의 것")가 판례 B("매뉴얼 없는 개선은 개선한 자의 것") 판결을 쉽게 만들고, B가 최종 사건을 움직인다. 손 표는 A와 최종 사건의 직접 유사도만 본다.
2. **판정관 × 판례 상호작용**: '오렌'(계약 중시)은 노동 판례에는 꿈쩍하지 않다가, 그 판례가 "계약서가 없었던 경우"라는 사실을 먼저 확인한 판결이면 움직인다. 손 표의 태그 가중치는 이런 조건부 반응을 표현하지 못한다.
3. **판례 충돌**: 회사 측 판례 "계약 우선"과 플레이어 판례 "돌본 자 우선"이 함께 있을 때, 판정관마다 어느 쪽을 의지하는지(J1b)가 갈린다. 손 표는 단순 상쇄한다.
4. **차이가 없어야 정상인 지점**: 직접 유사 판례 하나의 효과. 손 표와 Jev가 같은 방향이어야 한다(학습 가능성의 바닥).

### 7.3 A/B 테스트 설계
- **사전 측정(구현 전)**:
  - (a) 판례 0/2/4/6개 궤적 × 최종 사건 3개 × 판례 조합 10개 = 120요청(판정관 3명 묶음).
  - (b) 직접 판례 세트 vs 간접 판례 세트 비교 20쌍.
  - (c) 판례 순서만 바꾼 쌍 10개.
  - (d) 판정관 교체(같은 입력, 페르소나만 교체) 10개.
  - (e) 손 표 7.1의 예측 구간과 Jev 구간의 일치율.
  - 통과 신호(가설): (a) S가 판례 6개에서 0.15 이상 움직임. (b) 간접 효과가 직접 효과의 1/3 이상. (d) 판정관 간 구간 차이 평균 1구간 이상. (e) 손 표 일치율 60~85%(너무 높으면 표로 대체 가능, 너무 낮으면 학습 불가. C-R17의 기준을 이 후보에 맞게 조정한 가설값). (c)는 결과와 무관하게 순서 결정의 존치 여부를 정한다.
- **플레이 A/B**: 참가자 10명(가설), 교차 설계(Jev 2판, 손 표 2판). 같은 최종 사건, 같은 시작 후보.
- **지표**: 판결 예측 정확도(주기마다 플레이어가 판정관별 투표를 예측), "놀랐지만 납득" 비율, 판례 그래프 회고("어느 판례가 최종 사건을 움직였나" 질문에 대한 설명의 단계 수: 직접 1단계 vs 사다리 2단계 이상), 블라인드 선호, 3판째 상정 순서의 변화.
- **판정**: Jev 버전에서 2단계 이상 사다리 설명 비율이 높고 블라인드 선호가 2/3 이상이면 통과 신호. 손 표와 차이가 없으면 A03+는 "손 표 판례 게임"으로도 성립하므로, Jev의 역할을 판정관 성격 쪽으로 옮길지 재검토한다.

## 8. 대표 플레이 예시 (규칙 적용)

- 최종 사건: "광산 드론이 스스로 고친 채굴 경로는 회사 특허인가, 정비공 조합의 공동 권리인가." 판례 0개 사전 계산 S = 0.38. 판정관별 (인정, 부분 인정) 구간값: 하스 (0.75, 0.25) → c = 0.875, 오렌 (0.05, 0.05) → 0.075, 미로 (0.05, 0.25) → 0.175. S = 1.125 / 3 ≈ 0.38로 기각 구간이다.
- 판정관: 하스(전 엔지니어, 노동 중시), 오렌(회사 출신, 계약 중시), 미로(신중, 선례 중시).
- 주민: 양봉업자 '노아', 정비공 '바투', 관리인 '세린' 등 8명.

1. **1주기**(판례 0, 표 사용). 후보: 벌집 구조(노아 대 공동 정원회), 공용 세탁기 수리비, 야간 정수기 개선안, 화물칸 배정. 벌집 구조를 상정하고 주목 사실은 "노아가 3년간 벌을 돌봤다"를 고른다. 하스 (인정 0.75, 부분 0.25) → 0.875, 미로 (0.5, 0.5) → 0.75, 오렌 (0.05, 0.25) → 0.175. S = 1.8 / 3 = 0.60 → **인정**. 표결 2:1(오렌 반대, 소수 의견 1). 집행: 노아 생계 안정. 트리거: "공동 정원 꿀을 따로 팔아도 되는가" 사건이 생성된다.
2. **2주기**(경쟁자 주기). 회사가 "계약서에 없는 작업의 성과는 고용주 소유"를 상정해 판결된다. 하스 기각, 오렌 인정, 미로 인정(J1b: 미로가 의지한 것 = "다른 사실: 고용계약서가 존재"). S(회사 측) = 0.62 → 회사 인정. 판례 2번 = 회사 측 판례. 하스 소수 의견 1.
3. 플레이어는 "야간 정수기 개선안"(매뉴얼 없는 개선)을 고려한다. 예비 심리 1회(실시간): 주목 사실 "계약서에 야간 업무 조항이 없었다" → 하스 (0.95, 0.05) → 0.975, 오렌 (0.25, 0.25, 기각 0.5) → 0.375, 미로 (0.5, 0.25) → 0.625. J1b: 오렌 → "먼저 확인한 사실", 미로 → 판례 1(벌집). S = 1.975 / 3 ≈ 0.66 → 인정 예상. 오렌의 개별 투표는 기각(1위)이다. 상정 → 캐시로 같은 결과가 확정된다. 오렌 소수 의견이 2가 되어 **무게 1.5**로 상승하고 카운터는 0이 된다.
4. 오렌의 무게가 커졌으므로 최종 사건에서 오렌의 반대가 더 무겁다. 다음 주기에는 오렌을 움직일 사건, 즉 "계약서가 없었던" 사실을 가진 사건을 찾아야 한다. 집행 결과 바투의 거주가 "임시"가 되어(회사 판례의 집행) 새 트리거 사건 "바투의 공구는 누구의 것인가"가 열렸다. 이 사건은 최종 사건과 주제가 2개 겹친다(얻은 사건). 상정할 것인가? 지면 바투가 퇴거되어 퇴거 수가 1이 된다.

## 14. 종이 프로토타입 규칙 요약 (1쪽, 사람이 Jev 역할)

**준비물**: 최종 사건 카드 1장, 사건 카드 18장(기본 12, 트리거 6; 사실 3개, 주제 태그, 판결별 집행 효과, 트리거 조건 기재), 판정관 카드 3장(페르소나, 무게 칸, 소수 의견 칸), 주민 카드 6장(상태 태그 칸), 판례 기록지(6칸), 예비 심리 토큰 5, 고정 토큰 2, 보류 토큰 1, 막대 계산표.

**역할**: 플레이어 1명, 진행자 1명(집행, 트리거, 경쟁자, 점수 계산), **Jev 역할 1~3명**(가능하면 판정관마다 1명씩 따로. 판정관 사이의 차이가 실제로 생기는지 관찰하기 위해서다).

**Jev 역할 규칙**(C의 Q19 준수)
1. 판정관 카드, 판례 기록지, 이번 사건 카드(주목 사실 표시)만 본다. 플레이어와 대화하지 않는다.
2. 출력: 인정/부분 인정/기각 각각에 5구간 값(거의 없음/낮음/반반/높음/거의 확실 = 0.05/0.25/0.5/0.75/0.95)을 적되 합이 대략 1이 되게 한다. 그리고 "가장 의지한 것" 1개(판례 번호 또는 사실). **설명은 금지한다.**
3. 같은 판례 목록 + 같은 사건 + 같은 주목 사실이면 기록지대로 같은 답을 한다.
4. 오류 주입: 진행자가 주사위 6이 나오면 "이번엔 페르소나와 반대로" 쪽지를 준다.

**주기 진행**: (경쟁자 주기면 경쟁자 사건 판결) → 플레이어 예비 심리(선택) → 사건 상정 + 주목 사실 → 판결 → 진행자가 S 계산(무게 × (인정 + 0.5 × 부분)) → 판결 확정(≥0.55 인정, 0.40~0.55 부분, <0.40 기각) → 판례 기록 → 집행(주민 카드 태그 변경) → 소수 의견·무게 갱신 → 트리거 확인 → 다음 경쟁자 의도 공개.

**종료**: 6주기 후 최종 심리. 퇴거 3명이 되는 순간 즉시 패배.

**기록할 것**: 주기마다 플레이어가 판정관별 투표를 예측(말로) → 실제와 비교, 놀람/납득 체크, 상정 이유 발화(특히 "이 판례가 나중에…"), 판례 그래프 회고 질문에 대한 답.

**손 표 버전**: Jev 역할 대신 진행자가 7.1의 유사도 표·태그 가중치로 구간을 계산한다. 플레이어에게 버전을 알리지 않는다.
