## 1. 인터페이스 변경 사항 (v01 대비)
- **질문 형식 추가**
  - YN: "{판정자}는 {대상}이 {속성}이라고 판정하는가?" → 예/아니오
  - RUBRIC: "{판정자}가 매기는 {척도}는?" → 1~5
  - 둘 다 세계 안의 기관·기계 판정자에만 쓴다. 플레이어 산출물에는 쓰지 않는다(원칙 1).
- **캐시 키**: v01 키 + `model_version`. Jev 모델 버전이 바뀌면 L1을 무효화하고, L0(출시 캐시)는 재생성·재검증 파이프라인(N1 해법 검사 포함)을 다시 돈다.
- **캐시 3계층**(L0 출시 / L1 실제 Jev만 / L2 판 로컬·대체 판정)은 v01과 같다. 대체 판정은 L1에 쓰지 않는다.
- **의미 밀도 지표**(스키마 메타데이터, C5-X03)
  - D_log = Σ(log 템플릿별 슬롯 값 종류 수의 곱)
  - D_enum = context enum 조합 수
  - 보고 항목: D_log, D_enum, 그리고 "원칙 2 측정 문항 중 log 조작 문항 비율"(100%가 원칙).

### 2.2 2단계: 후보별(사전 등록 판정표)

공통 조건 C0~C5는 v01과 같다. 다만 **조작은 log 슬롯으로만** 한다.

**공통 판정표(v02, 전 후보)**

| 지표 | P0 확정 | 수정 후 1회 재측정 | 해소 |
|---|---|---|---|
| Δ관련 = 변경률(C1) − 변경률(C3) | < 5%p | 5~15%p | ≥ 15%p |
| 대조군 변경률(C3) | ≥ 30% | 15~30% | < 15% |
| 납득률(1위가 바뀐 문항) | < 50% | 50~67% | ≥ 67% |
| **원칙 2 판정**: 조작 문항 손 표 일치율(A) + 불일치 사례 블라인드 쌍비교 Jev 선호(P) | A > 90% → 원칙 2 실패 신호. **또는** P < 40% → Jev 차이는 잡음(C-R03) | A ≤ 90%이고 40% ≤ P < 60% | A ≤ 90% 그리고 P ≥ 60% |
| 학습 불가 신호 | A < 40% 그리고 납득률 < 67% | — | — |

- 쌍비교 절차: 불일치 사례마다 같은 입력에 Jev 1위와 손 표 1위를 A/B 무작위 배치로 제시한다. 평가자 3명이 각자 고르고, 다수결로 사례 승자를 정한다. P = Jev 승 사례 / 전체 불일치 사례.
- 불일치 사례가 30개 미만이면 P를 판정에 쓰지 않고 "표본 부족 → A만으로 판단, 재측정 권고"로 둔다.

후보별 추가 지표는 각 명세 7.3을 따르되, 다음을 보정한다.
- **A01+**: J3 다양성은 기록용(생사 무관). 원칙 2 문항은 범주 소문 × 범주 밖 장면, 두 부분 소문 잇기에 집중한다.
- **N1**: 기억 흘리기 문항은 source = 직접 기록만 쓴다.
- **A03+**: (d) 판정관 교체 P0 → 배심 변형 측정치로 교체 판단(배심 구성 규칙 6장).
- **N3**: Δ의미 문항은 "손 표 상황 태그가 같고 log 내용만 다른" 쌍으로 만든다(C5-X03).

**2단계 분기**: 후보별로 아래 셋 중 하나로 정한다.
- 해소 → 플레이 A/B(디지털 최소 프로토타입)로.
- 재측정 → 허용 수정 1회 후 재측정.
- P0 → 명세의 사전 등록 대안(분기 하루, 주민 배심, 커버 정체성/N2 교체)으로 가거나 중단. 디렉터 확인.

### 2.3 측정과 종이 프로토타입의 관계
- 종이 프로토타입(PAPER_PROTOTYPE_KIT_v01)은 Jev 실측과 **병렬로 즉시** 시작한다. 종이는 경험(좌절, 지름길, 학습 곡선)을, 실측은 판정 품질을 본다. 서로의 결과로 상대 기준을 바꾸지 않는다.

- 토큰: 요청 평균 2.5k(E7은 8k) 가정 시 약 15M 토큰 → 서드파티 단가 $0.042/M 기준 **약 $0.63**. 단가가 10배여도 $6 수준이다.

## 4. 운영 정책

### 4.1 사전 등록(C5-X05)
1. 문항 파일(JSONL), 손 표 코드, 판정표 버전을 저장소에 올리고 SHA-256 해시와 날짜를 `PREREG.md`에 기록한다.
2. 측정 실행 로그에 해시를 남긴다.
3. 측정 후 문항·기준 변경은 새 버전(새 해시)으로만 한다. 재측정은 판정표의 "허용 수정" 범위로만 한다.

### 4.2 평가자 블라인드
- 평가자는 조건(C1/C3 등)과 출처(Jev/손 표)를 모른다. 문항 작성자는 평가하지 않는다.

### 4.3 모델 버전
- 측정 보고서에 Jev 모델 버전과 날짜를 기록한다. 버전이 바뀌면 0단계와 E2를 재실행한다(약 560질문).

## 부록: 4차 파도 N17, N20 시스템 평가 (포트폴리오 슬롯 후보)

**N17 블랙박스 감사관.**
- **루프와 결정**: 루프는 잘 닫힌다. 주간 실제 심사(결정론 집행), 실험 예산 8, 양식 수정, 지표 재심사로 이어진다. 플레이어의 결정(어떤 필드를 통제 변수로 둘지, 어떤 양식을 고칠지)은 정보 획득과 개입 사이의 실제 트레이드오프라 의미 있는 선택이다.
- **판정 형식**: YN + RUBRIC 30장 묶음이다. 그래서 이 후보의 생사는 엔진 1단계 E7(묶음 재현성·간섭)과 0단계 L-d로 대부분 판별된다. 측정 비용이 매우 싸다(약 20요청).
- **원칙**: 원칙 1은 깨끗하다(판정 대상 = 세계 안 신청서). 원칙 2는 다른 어떤 후보보다 직접적이다. 숨은 규칙이 문자 그대로 Jev다.
- **시스템 위험 셋**
  1. 콘텐츠 품질을 디자이너가 통제할 수 없다. 발견할 만한 경향이 있는지가 Jev에 달렸다. E8 덧셈 오차가 너무 낮으면 "단순한 가중치 찾기", 너무 높으면 "추론 불가"다.
  2. 모델 버전이 바뀌면 같은 심사기가 다른 경향을 갖는다. 판 단위 경험에는 문제가 없지만, 공략·공유 문화에는 문제가 된다. 모델 버전 고정 캐시 정책으로 다룬다.
  3. 현실의 AI 편향을 다루는 소재 판단은 디렉터 몫이다.
- **판단**: T1과 무관한 **보험 슬롯 1순위**로 권한다. 0단계 L-a·L-c가 P0여도 남는 몇 안 되는 후보다.

**N20 표본실.**
- **루프와 결정**: 탐사·채집·분석·제작의 결정론 뼈대가 Jev 없이도 선다(Q5 강함). 분석 예산과 "법칙을 믿고 분석 없이 쓰기" 도박이 의미 있는 선택을 만든다.
- **판정 형식**: 표본당 YN 8개다. 표본은 게임이 생성하는 유한 집합이라, 판 시작 시 그 판의 표본 전체를 한 번에 판정(묶음)해도 된다. 즉 그 판의 역사가 판정 입력에 들어가지 않고, **실시간 Jev의 필요성은 약하다**(BRIEF의 "실시간은 그 판만의 것에" 방향과 어긋남). 다만 BRIEF v02 기준(체감 차이)으로는 조합 예외가 체감되는지가 기준이다. 그것은 E8 덧셈 모델 오차로 바로 판별된다(오차 < 10%면 표로 충분).
- **시스템 위험 둘**
  1. 지구적 특징("불에 타는가")은 상식 정답이 있어 C-R03이 일부 노출된다. 외계 특징 위주로 쓴다.
  2. 필요한 성질을 가진 표본이 판에 없으면 진행이 막힌다. 판 생성 시 전 표본을 판정한 뒤 필요 성질의 존재를 검사·재생성해 해결할 수 있다. 이것이 사전 판정의 장점이다.
- **판단**: 보험 슬롯 2순위. N17과 같은 YN층에 기대므로 둘을 함께 슬롯에 넣으면 분산 효과가 작다. 하나만 고른다면 원칙 2 근거와 Jev 고유성이 더 강한 N17을 권한다.
