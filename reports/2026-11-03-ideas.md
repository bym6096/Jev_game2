### Idea 1: 내가 쓴 이름들 (덱 = 주인공 덱빌더)
| Field | Content |
|---|---|
| **Core loop** | 전투 → 보상으로 빈 구슬 1개 → 이름을 새겨 카드 생성 → 덱에 추가 → 덱의 이름들이 주인공 원형을 바꿈 → 다음 전투. 실패 = 체력 0, 또는 구슬이 한계를 넘어 파손 |
| **Why now** | 결합형 덱빌더가 막 열림: Vampire Crawlers는 Metacritic 81~87, 모바일 10/12 출시 (Wikipedia, 2026-04·10). 소재만 다른 덱빌더는 10월 한 달에 4개 이상 나와 포화 쪽 (Rogueliker, 2026-10). 그래서 소재가 아니라 입력 방식이 차별점이어야 함 |
| **Lifecycle stage** | 결합형은 emerging~rising, 테마형은 saturated (추정). 창 길이는 확인 못 함 |
| **Twist** | 음소거 3초 클립: 플레이어가 단어를 쓰면 구슬에 새겨지고, 호버하면 속성·효과가 뜨고, 덱이 바뀌면 주인공 초상이 변함 |
| **Keep vs change** | 유지: 덱 빌딩과 시너지를 발견하는 재미(28개 조합 효과가 "오 이런 조합이 있네"를 줌). 변경: 카드를 고르지 않고 직접 지음, 위험 감수는 파손 규칙(금박 한계 12 등)으로 |
| **Automation lever** | 콘텐츠는 이름 → Jev가 속성(98)·효과(64)·고유(64)를 판정해 자동 생성. 견본 44장을 이미 자동 생성함. 전투 균형은 자동 검증 장치 없음 |
| **Social hook** | 덱 이름 목록 + 주인공 원형 카드. 단 정답 이름 공유 위험(한계·파손·12% 가챠로 완화) |
| **Monetization** | 근거 없음. PC 유료 판매로 가정하되 이번 스캔에서 가격대는 확인하지 못함 |
| **MVP scope** | HANDOFF의 종이 프로토타입 범위: 적 3종, 빈 구슬 보상 3번, 3전투. 웹 2D. 약 3~4주 (estimate) |
| **Not in MVP** | 패시브 실효과, 13개 언어(한국어+영어만), 메타 성장, 상점, 3D |
| **Kill switch** | 사내 기준(시장 벤치마크 아님): 테스터가 한 판 뒤 안내 없이 두 번째 판을 시작하는 비율. 임계값은 디렉터가 정함. 시장 지표는 `tracking-game-metrics`로 나중에 확인 |
| **Risks** | ① 전투·마나 균형이 미검증(HANDOFF: 밸런스는 보류 중) → 전투 3판으로 먼저 확인 ② Jev 확률이 ±0.08 흔들려 경계값에서 카드가 바뀜 → 만든 카드는 JSON째로 저장 |
| **Scores** | 2 · 3 · 3 · 2 · 3 · 3 · 4 = 20/35 |

### Idea 2: 한 단어 원정 (일일 10방 웹 로그라이트)
| Field | Content |
|---|---|
| **Core loop** | 방마다 적(7계열 중 하나)이 나옴 → 낡은~금박 구슬 한 개에 단어 하나를 새김 → Jev가 속성·세기를 판정 → 상성과 세기로 피해/방어 결정 → 10방을 끝까지 또는 체력 0. 매일 같은 적 순서(시드 고정) |
| **Why now** | LLM을 게임 규칙에 쓰는 사례는 초기: Hex Judge(2026-07-16, $5.99, 로컬 LLM) 외에 뚜렷한 경쟁작을 이번 스캔에서 못 찾음 (개발사 보도자료, 2026-07). 반응 수치는 없음 |
| **Lifecycle stage** | emerging (추정). 창은 확인 못 함 |
| **Twist** | 음소거 3초 클립: 적이 나타나고, 플레이어가 한 단어를 쓰면 구슬이 새겨지고 즉시 피해가 터짐. 한 방이 3~5초 |
| **Keep vs change** | 유지: 방 단위의 짧은 판(하데스류 취향), 계열 상성. 변경: 무기·스킬 대신 단어 하나가 전부 |
| **Automation lever** | 적은 (계열, 약점 속성) 조합을 시드로 자동 생성. 풀 수 없는 방은 없음(98개 속성 중 상성이 맞는 단어가 항상 존재). 요청당 질문을 속성·효과·세기 정도로 줄이면 더 가벼움 (estimate, 실측 필요) |
| **Social hook** | 10방 결과를 구슬 색과 크기의 한 줄로 공유(단어는 숨김 → 스포일러 방지). 같은 적으로 겨루는 일일 챌린지 |
| **Monetization** | 근거 없음. 웹 포털 조건은 공식 문서로 확인 전. 광고 휴식 지점은 방 사이에 자연스럽게 있음 |
| **MVP scope** | 한 화면: 적 표시 + 구슬 입력 + 결과 줄. 계열 상성표, 시드 고정, 한국어+영어. 기존 `forge.py`와 서버 재사용. 약 1~2주 (estimate) |
| **Not in MVP** | 덱과 주인공 성장, 계정, 리더보드, 13개 언어, 효과 조합 |
| **Kill switch** | 사내 기준: 한 판 뒤 다시 하기 비율, 같은 단어 반복 비율(정답 이름이 퍼졌는지). 임계값은 디렉터가 정함 |
| **Risks** | ① 정답 이름이 공유되면 일일 판이 풀려 버림 → 구슬 등급 한계와 파손, 12% 가챠, 공유 시 단어 숨김 ② 공개 시 초당 요청 한도(429) → 지금은 비공개 장난감이라 급하지 않음, 일일 판 한정 캐시 가능 |
| **Scores** | 4 · 4 · 3 · 2 · 3 · 3 · 4 = 23/35 |

### Idea 3: 말의 주사위 (확률이 단어에서 나오는 쿼터 로그라이크)
| Field | Content |
|---|---|
| **Core loop** | 라운드마다 목표 점수(쿼터)가 오름 → 보유한 구슬(주사위)에 단어를 새김 → Jev가 낸 확률 분포가 그 구슬의 눈 가중치가 됨 → 굴려서 점수 획득 → 쿼터 미달이면 끝 |
| **Why now** | 클로버핏은 쿼터 + 시너지 루프로 100만 장 (Wikipedia, 2025-11)이지만 같은 루프의 변주는 포화 쪽 (Rogueliker, 2026-10). 차별점은 확률표를 개발자가 설계하지 않고 언어에서 얻는다는 것 |
| **Lifecycle stage** | 루프는 peaking, 확률 원천은 emerging (추정) |
| **Twist** | 음소거 3초 클립: 단어를 쓰는 순간 막대그래프(눈별 확률)가 단어에 따라 휘어지고 곧바로 굴러감. 슬롯·돈 연출 없이 주사위와 막대로만 표현 |
| **Keep vs change** | 유지: 쿼터가 오르는 압박과 시너지 발견. 변경: 보상 표를 손으로 짜지 않고 단어가 만드는 분포로 대체. 도박 연출은 뺌(클로버핏은 심의 논란 기사가 있었음, PC Gamer 헤드라인, 확인 필요) |
| **Automation lever** | 구슬마다 Jev 분포 1회 판정(속성 98개 질문 하나로 분포가 나옴, HANDOFF 실측). 분포는 저장해 재현 |
| **Social hook** | "이 단어는 이런 분포" 막대 그래프 카드, 쿼터 돌파 기록 |
| **Monetization** | 근거 없음 (PC 유료 가정) |
| **MVP scope** | 한 화면, 구슬 슬롯 3~5개, 쿼터 8라운드, 눈 종류 7계열로 축약. 약 2~3주 (estimate) |
| **Not in MVP** | 덱/주인공, 다국어 13개, 메타 성장, 3D |
| **Kill switch** | 사내 기준: 단어를 바꿔 가며 분포를 비교하는 행동이 실제로 나오는지(관찰), 한 판 뒤 재시작 비율 |
| **Risks** | ① 분포를 직관적으로 읽기 어렵다 → 막대그래프와 상위 3개만 노출 ② 클로버핏의 변주처럼 보일 위험 → 막대 변형 연출을 클립의 중심에 둠 |
| **Scores** | 3 · 3 · 3 · 2 · 3 · 3 · 4 = 21/35 |

## 추천
**2번 「한 단어 원정」을 먼저 만들기를 권합니다.** 이유: 가장 가볍고(기존 forge 재사용, 1~2주 추정), 세 아이디어가 공통으로 기대는 질문, 즉 "단어를 새겨 적과 맞붙는 순간이 재미있는가"를 가장 싸게 검증합니다. 이 판정이 재미있다면 1번의 덱 성장과 3번의 확률 분포는 그 위에 얹을 수 있습니다. 반대로 2번이 재미없다면 1번에 몇 주를 쓰기 전에 알 수 있습니다.

단, 2번도 23점이라 GO 기준(24 이상)에는 한 점 모자랍니다. 근거 없이 점수를 올리지 않았고, 시장 쪽 근거(수익 구조, 일일 챌린지의 공유력)는 아직 비어 있습니다.
