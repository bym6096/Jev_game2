### 확인 메모
- F1 이유: `\b(attack|mana|hp...)\b` 는 숫자도 `\w`라서 `mana5`는 단어 경계가 없다. `5mana`도 같다. Python과 JS 동일 결과.
- F2 이유: 스탯어 검사는 이름 전체 문자열에 대한 정규식이라 글자 사이에 공백이 있으면 못 찾는다. 공백은 중립이라 언어 판정에도 안 걸린다.
- F3 이유: `script_of`의 hangul 범위가 U+3130-318F와 U+1100-11FF를 통째로 허용하고, 그 안에 눈에 안 보이는 U+3164, U+115F, U+1160이 있다. `strip()`도 이 문자를 안 지운다.
- F4 이유: CJK 길이는 `name.replace(" ","")`로 센다. 공백 개수 제한이 없다. 영어는 공백도 세므로 14자에서 막힌다.
- F13: 서버(Python)가 최종 판단이므로 BOM은 서버가 거부한다. 클라이언트가 "통과"라고 보여 준 뒤 서버 오류가 날 수 있다.

## 프롬프트 틀(`<<<name>>>`) 점검
- 허용 문자 집합은 한글/가나/한자/ASCII 영문/`-`/`'`/숫자/공백뿐이다.
- `<` `>` `\n` `\r` `\t` `"` `\` 는 모두 "other"로 거부된다. `a>>>b`, `<<<`, `a\nb` 확인함.
- 따라서 이름으로 `>>>`를 닫거나 새 줄로 지시문을 넣는 것은 불가능하다.
- 안에 남는 건 `'`와 `-`와 공백뿐이다. 공백은 무제한(F4)이므로 프롬프트 크기만 문제다. 앞뒤 공백은 `strip()`으로 제거된다 (build_request에는 strip된 이름이 들어감).
- 다만 영어 14자 안의 자연어 지시문(F16)은 규칙으로 못 막는다. guard 질문에 맡겨진 상태.
- check_deck의 오류 메시지는 `카드 이름 '{n}'`으로 원문을 되돌려 준다. 길이 제한 없는 입력(F4 공백 등)이 그대로 응답에 실린다. 화면에 `textContent`로 쓰면 안전하지만 `innerHTML`이면 위험하다. (이번엔 렌더링 코드는 확인하지 않음.)

## 권장 수정 (구현하지 않음)
1. 스탯어 검사 전에 이름을 정규화한다: 공백, `-`, `'`를 모두 지운 사본으로도 `_STAT`를 검사한다 (F2). 영어는 `\b` 대신 "글자 경계"(`(?<![a-z])...(?![a-z])`)를 써서 `mana5`, `5mana`를 잡는다 (F1). 복수형은 `s?`를 허용한다 (F8).
2. 숫자 3자리 검사도 사본(공백, `-`, `'` 제거) 위에서 한다 (F5, 공백 섞은 `1 0 0 0`은 이미 "숫자만" 오류로 막힘).
3. 글자 없는 이름을 거부한다: `-`, `'`는 중립으로 취급해서 "scripts 비어 있음"과 같이 처리한다 (F6).
4. 보이지 않는 문자를 거부한다: U+3164, U+115F, U+1160, U+FFA0, U+3099/309A 등. 더 단순하게는 한글을 U+AC00-D7A3 + U+3131-3163(자음/모음)로, 가나를 U+3041-3096, U+30A1-30FA, U+30FC로 좁힌다 (F3, F11). 자모만 쓰는 이름(F10)을 막을지는 기획 결정.
5. 전체 길이 상한을 둔다. 예: 공백 포함 20자, 또는 연속 공백 1칸으로 합친 뒤 검사 (F4). 입력 단계에서 `re.sub(r"\s+"," ",name)` 후 `strip`을 쓰면 캐시 키 중복(F15)도 줄어든다. 캐시 키는 소문자화 + 공백 제거 사본으로.
6. 스탯어 목록 보강 (F7): def/defense/lv/lvl/level/health/life/speed/armor/str/atk, 레벨/힘/생명/속도/마력/파워/방패, 攻擊/體力/体力/生命/魔法. 목록은 끝이 없으므로 "숫자가 하나라도 있는 이름에서는 스탯어 + 숫자 허용 안 함"보다 "이름 속 숫자는 최대 2자리 한 덩어리"처럼 숫자 자체를 줄이는 쪽이 더 단단하다.
7. 정규화를 먼저: `unicodedata.normalize("NFC", name)`를 JS(`name.normalize("NFC")`)와 Python 양쪽 첫 줄에 넣어 NFD 오거부를 없앤다 (F12).
8. strip 차이 통일: 양쪽 모두 같은 정규식으로 앞뒤 공백을 지운다. 예: `re.sub(r"^[ \t\r\n]+|[ \t\r\n]+$","",name)` (JS도 동일 식). 그러면 BOM, 0x1c-0x1f, 0x85 차이가 사라진다 (F13).
9. server.py: `str(body.get("name",""))`로 감싼다 (F14).
10. 이름 규칙이 못 막는 의미적 지시문(F16)은 guard 질문을 계속 유지. 규칙 쪽 추가 조치는 불필요.

## 올바르게 막힌 것 (시도했지만 거부됨)
- 전각 숫자 `１２３`, 원문자 `①`, 아랍 인도 숫자 `٣٣٣`, 데바나가리 숫자 `१२३`, 위첨자 `²` `³³³`, 로마 숫자 `ⅲ`, `〇` `一〇〇` : 모두 "쓸 수 없는 문자".
- 전각 영문 `ＡＴＫ` `ａｂｃ`, 키릴 `аtk 5`(앞 글자가 키릴 a), 반각 가타카나 `ｱｲｳ`, 켈빈/긴 s `ſ`, `İ`, `ß`, `ᴀ` : 거부.
- 제로폭 문자 `가\u200b나`, 결합 악센트 `가\u0301`, `e\u0301`, `é` : 거부 (길이 제한 회피용 결합 문자 불가).
- 이모지 `😀`, 보조 평면 한자 `𠀀` (서로게이트쌍): 거부. JS는 `[...name]`으로 코드포인트 단위로 세므로 Python과 길이가 같다.
- 줄바꿈 `a\nb`, 탭 `a\tb`, NUL `가\x00`, `<<<`, `a>>>b` : 거부.
- 앞뒤 줄바꿈 `\nabc\n`, 앞뒤 전각 공백 `\u2003abc`: strip 되어 통과(정상). 안쪽 U+2003, U+00A0 등은 other로 거부.
- `\u180eabc` (몽골 모음 구분자): 양쪽 모두 거부.
- 스탯어 + 숫자의 기본형: `공격 99`, `공격력99`, `mana 0`, `Mana  5`, `coSt 5`, `mana-5`, `atk 5`, `攻击99`, `攻撃5`, `마나5`, `マナ5` : 거부 (대소문자와 다중 공백 포함). `mana\x005`도 거부(NUL 때문에 other가 아니라 스탯 검사에서 걸림).
- 3자리 이상 연속 숫자 `공격 999`, `1 000 000`(공백 사이는 숫자만 오류), 숫자만 `9 9 9`, `1 0 0 0` : 거부.
- 혼합 언어 `한a`, 혼합 한자+가나 → ja 판정은 정상(`ひらがな漢字` 6자 통과, 7자 이상 거부). 한국어 8자 / 영어 14자 / 중국어 4자 / 일본어 6자 경계값 모두 정상.
- 영어에서 공백은 글자 수에 포함(14자 제한 정상). 한국어 `가 나 다 라 마 바 사 아`는 8자로 계산(의도대로).
- 무작위 2만 개 + 단일 문자 전수 비교에서 Python/JS 불일치는 F13의 공백류(U+FEFF, U+001C-001F, U+0085)뿐이었다. `\b` 정의 차이(Python 유니코드, JS ASCII)는 허용 문자가 ASCII뿐이라 실제 차이를 만들지 못했다.
